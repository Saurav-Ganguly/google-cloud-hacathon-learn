### Built: PDF Explainer sandbox (`test/code_runner/`)

Per [[plans/luminous-stirring-swing]] — instead of a toy calculator, the
`code_executor` sandbox is a 5-agent pipeline that turns a hardcoded PDF
into a Tailwind-styled HTML explainer page, with charts drawn live by
Gemini's code executor.

Final pipeline:

```
SequentialAgent  pdf_explainer
  intent_capturer    (Gemini, output_schema=UserIntent)
  pdf_extractor      (LiteLlm deepseek + FunctionTool extract_pdf_text)
  structure_planner  (Gemini + BuiltInPlanner, output_schema=ExplanationPlan)
  chart_maker        (Gemini + code_executor=BuiltInCodeExecutor)
  html_renderer      (Gemini, free-text HTML output)
```

`test/code_runner/agent.py` is the canonical annotated template for
`code_executor` patterns. End-to-end run verified: 5 charts captured, 5
embedded inline, 424KB self-contained HTML written, opens in browser.

### Four real bugs debugged (all vaulted)

1. **Gemini code executor not supported on `gemini-flash-latest`.** The
   `*-latest` aliases on Vertex `global` don't expose the built-in
   code-execution tool. Fix: pin `chart_maker` to `gemini-2.5-flash`
   explicitly. Vaulted in [[concepts/adk-code-executor]] §HARD
   CONSTRAINTS-1 and [[concepts/adk-llm-agent-config]] §10.

2. **`part.code_execution_result.output` ≠ `part.text`.** First version
   of `chart_maker_callback` only read `part.text` and missed every
   chart — the printed b64 markers live in
   `part.code_execution_result.output`. Vaulted in
   [[concepts/adk-code-executor]] §"Reading what the executor produced".

3. **ADK instruction templater eats `{{...}}`.** ADK uses regex
   `{+[^{}]*}+` to find state-var refs — NOT Python's `.format()`. So
   `{{title}}` does NOT escape to a literal `{title}`; it matches as a
   single lookup of `state["title"]` and KeyErrors out. Verified by
   reading the stack trace pointing at
   `google/adk/utils/instructions_utils.py:124`. Fix: don't use brace
   characters in instructions at all — use angle-bracket placeholders
   or all-caps tokens. Vaulted in [[concepts/adk-llm-agent-config]] §9.

4. **Never pipe base64 (or any large opaque blob) through an LLM.**
   First version of `html_renderer` was given the full base64-PNG list
   in its prompt and asked to embed each as `<img src="data:..."
   alt="...">`. Result: 92KB of repeating garbage b64 before hitting the
   output token cap. Canonical fix: model emits placeholder markers
   `<!-- CHART: title -->`, the `after_agent_callback` runs a Python
   regex sub to splice in real `<img>` tags from `state["chart_images"]`.
   Architectural pattern, not just a fix. Vaulted in
   [[concepts/adk-code-executor]] §"Anti-pattern: piping LLM-generated
   opaque blobs".

### Bonus side-quest: thinking-budget on schema-fill agents

While debugging the hang on `html_renderer`, the diagnosis was the same
Gemini-2.5 hidden-thinking bug from yesterday (unlimited thinking
budget on free-text generation → looks like a multi-minute hang). Fix:
`thinking_config=ThinkingConfig(thinking_budget=0)` on `html_renderer`
just like the schema-fill agents in `test/LlmDebator/agent.py`. The
rule generalises: **any agent that doesn't need to reason should have
`thinking_budget=0`** — HTML generation is transcription, not
reasoning.

### Final state shape after a run

```
user_intent     : UserIntent dict
pdf_text        : extracted PDF text (~30k chars)
explain_plan    : ExplanationPlan dict (sections + visual_hint)
chart_images    : list[{section_title, b64_png}]
chart_titles    : list[str]  (just titles, for html_renderer's prompt)
output.html     : 424KB self-contained Tailwind HTML on disk
```

`test/code_runner/test.pdf` (11-page CAG audit paragraph). Pipeline
produced 5 sections, 5 charts, all charts embedded inline as data URIs
in the final HTML.
