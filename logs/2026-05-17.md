### Built `arch-social-agent` — 3-agent sequential pipeline

Scaffolded and built a multi-agent pipeline at `arch-social-agent/` using ADK's `SequentialAgent`. Three sub-agents run in order: `research_agent` uses `google_search` to find top 3 architectural news stories → `strategy_agent` picks the best story and writes a LinkedIn post + crafts a detailed Imagen prompt (structured output via `StrategyOutput` Pydantic model, `output_key="strategy_output"`) → `image_agent` calls a custom `generate_image` tool that hits `gemini-3.1-flash-image-preview` with `response_modalities=["IMAGE", "TEXT"]` and saves the PNG to `output/`. State flows between agents via `{output_key}` injection in instructions. Factory functions used for sub-agents to avoid "agent already has parent" error.

End-to-end test passed on first run: agent searched for real architectural news (MVRDV Carbon Confessions, Studio Gang mass-timber theater, Melbourne Design Week AI talks), wrote a LinkedIn post, and generated a matching dark cinematic gallery image saved to `output/1779011351.png`. Interactive web UI running via `uv run adk web . --port 8080`.

### Local-run runbook created — `agents-cli playground` is broken on v0.1.3

Root-caused why the `adk web` UI showed `ERR_CONNECTION_REFUSED`: `agents-cli playground` shells out to `uv run adk web . --host 127.0.0.1 --port 8080`, and that arg form errors with an `adk web` usage error — the server never starts. Workaround: run `uv run adk web . --port 8080` directly (server stays up until Ctrl+C; verified listening via curl → HTTP 307 → `/dev-ui/?app=app`). Also confirmed connection-refused = server simply not running (timed-out test runs exit). Captured all of this plus the `PYTHONUTF8=1` requirement and the test-script vs web-UI options in a new definitive runbook [[configs/run-agent-locally]]; linked from [[index]] and cross-linked from [[configs/agents-cli-setup]].

Two Windows blockers hit and resolved:
- `agents-cli deploy` calls `gcloud` via Python `subprocess.Popen` without `shell=True`, so `.cmd` is never resolved → `FileNotFoundError` regardless of PATH. Workaround: run raw `gcloud beta run deploy` directly (use `agents-cli deploy --dry-run` to get the exact command).
