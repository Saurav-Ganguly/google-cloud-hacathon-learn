### Architecture revised mid-build (twice)

Started with yesterday's plan (`SequentialAgent[topic_refiner, LoopAgent(pro,
con, critic, escalation_checker), judge]`). Two revisions during the build:

1. **Added `fact_check_agent`** between the loop and the judge after asking
   "should judge ground via google_search?". Hit the
   `output_schema`-disables-tools constraint and split the work:
   `fact_check_agent` (Gemini + `google_search`, plain text) →
   `judge_agent` (Gemini + `output_schema=Verdict`, no tools). The
   "research-then-structure" pattern.
2. **Replaced the LoopAgent + critic with a fixed 2-round Pro/Con
   alternation** at user request: `pro_r1 → con_r1 → pro_r2 → con_r2`. The
   original loop design had Con always getting the last word against Pro's
   single opening; the 2-round symmetric design is fair (each side opens
   AND closes its own line).

Final pipeline:
```
SequentialAgent(debate_arena)
  topic_refiner (Gemini)
  pro_agent_r1  (LiteLlm openrouter/google/gemma-4-26b-a4b-it,  hot temp)
  con_agent_r1  (LiteLlm openrouter/deepseek/deepseek-v4-flash, cold temp)
  pro_agent_r2  (same gemma — rejoinder)
  con_agent_r2  (same deepseek — closing)
  fact_check_agent (Gemini + google_search, plain text)
  judge_agent (Gemini + BuiltInPlanner + include_contents='none')
```

### Two real bugs debugged (logged as gotchas)

1. **First run**: `topic_refiner` emitted only `'{\n'` then truncated →
   `Invalid JSON: EOF while parsing an object`. Root cause: Gemini 2.5
   Flash has hidden thinking ON by default, and thinking tokens count
   against the response budget. With `max_output_tokens=400`, hidden
   thought ate the budget. Fix: set
   `thinking_config=ThinkingConfig(thinking_budget=0)` on schema-fill
   agents that don't need to reason, and stop setting tight
   `max_output_tokens` (the default cap is generous).
2. **Second run**: `con_agent_r1` truncated mid-string at column 384. Same
   class of bug but on the OpenRouter side — bumped output budget by
   removing `max_output_tokens` entirely.

Both lessons vaulted in [[concepts/adk-llm-agent-config]] §7 + §8.

### `litellm` was missing from the project venv

`uv run python -c "from test.LlmDebator import agent"` raised
`ImportError: LiteLLM support requires: pip install google-adk[extensions]`
because the project's `.venv` (the one `uv run` uses) didn't have
`litellm` installed — only `caveman-compress/.venv` did. Fix: `uv add
litellm` to install it into the project's `.venv`. Going forward `uv run`
will work for any agent using `LiteLlm(...)`.

### Logging / UX upgrade

Every agent has an `after_agent_callback=make_logger(...)` that:
- prints a labeled banner to the `adk web` terminal
  (`agent_name (model) -> state[key]` + pretty-printed JSON/text)
- returns a `types.Content` that REPLACES the chat bubble with
  `agent_name  (model_label)\n\n{output}` so the adk web UI shows which
  agent + model produced each bubble.
- The judge's logger sets `dump_full_state=True` so the terminal also
  prints the entire accumulated session state at the end of every run —
  useful because adk web's State tab shows per-event delta, not cumulative.

### Final state shape after a run

```
debate_topic    : DebateTopic dict
pro_case_r1     : ProCase dict
con_case_r1     : ConCase dict
pro_case_r2     : ProCase dict
con_case_r2     : ConCase dict
fact_check      : plain text (with web citations)
verdict         : Verdict dict (winner_label, winner_model, reasoning, scores)
```

End-to-end run verified in `adk web` with the topic "should there be only 4
days working in India (and 3 days holiday), instead of 5 days working at
present, in India". Con (deepseek-v4-flash) won 9 vs 7 with India-specific
grounding (90% informal-sector argument, peak-energy from coal, SME
impact). Fact checker did real `google_search` grounding visible as search
chips in adk web.
