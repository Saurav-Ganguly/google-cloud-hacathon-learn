### Phase 2 — The big course-correction (templating syntax)

Mid-build, while wiring `prompt_builder`, dug into
`utils/instructions_utils.py:127-149` to verify the
`{ClassName.field}` syntax I'd documented in
[[concepts/adk-graph-workflows]] yesterday. Result:

**`{ClassName.field}` does not exist.** `inject_session_state` only
substitutes `{simple_identifier}` (optionally with `app:` / `user:` /
`temp:` prefix or a `?` optional marker). Anything that isn't a valid
Python identifier — including `ClassName.field` and the
`<ClassName.field from source_node>` syntax — is left literal in the
prompt.

The ADK 2.0 docs are wrong (or the docs describe a future feature). The
WORKING pattern is:
1. Upstream `FunctionNode` writes individual scalars to `session.state`
   via `Event(state={...})`.
2. Downstream Agent templates each value with `{simple_key}`.

Implemented exactly this: `split_prompts` after `prompt_builder` unpacks
`ResearchPrompts.{idea, market_prompt, tech_prompt, ...}` into individual
state keys; each research agent's instruction uses `{idea}`,
`{market_prompt}` etc. directly.

### Phase 4 — Observability layer

Shared `tracing.py` provides:
- `emit_enter(name, payload_summary)` / `emit_exit(name, payload_summary)` —
  used by FunctionNodes: print to stdout AND return `Event(message=...)`.
- `make_before(name, model)` / `make_after(name, model, output_key)` —
  Agent before/after callbacks; print a banner to stdout, optionally
  replace the chat-bubble in adk web with a labelled version.

Every node now traces to both channels. Console shows
`[node_name] ENTER/EXIT` lines as the graph runs; adk web shows the
same lines as `message` events plus full agent outputs.
